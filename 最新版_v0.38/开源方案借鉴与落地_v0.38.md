# 开源成熟方案借鉴与落地 · v0.38

结论：**不换引擎**，继续单文件 HTML + 每轮增量补素材；本轮沿用已落地约定，未引入第三方代码。

| 借鉴 | 已落地 | 本轮复用 |
|---|---|---|
| WebGAL `background/` 与 `figure/` 分层 | `LAYOUT_RULES.layers` | 新特效层 z=4 在角色(6)后、暗角(5)前 |
| WebGAL `changeFigureDiff` 只换差分 | `applyExpr()` 只换 src | `QPOSE38` 按关卡查表叠加，不覆盖旧差分 |
| Konva `fitContain()` / PixiJS Layout | `fitBox()` + 自动分层 | 8 层统一 `contain`、85px 安全边 |
| Ren'Py `zorder` / interact.js `restrictRect` | 声明式边界 + 候选位最小重叠 | 特效层 `pointer-events:none`，不抢立绘拖拽 |
| W3C Pointer Events / Phaser 输入 | 小游戏与立绘统一事件流 | 本轮未改，回归通过 |
| W3C MediaRecorder / getUserMedia | `HuskyVoice.record()` | 录音 / 导入接口回归通过 |
| WCAG 2.5.7 | 键盘 + 单指针替代路径 | 特效层不影响可点击控件 |
| Bun Standalone HTML / silos-packer | 全内嵌零外部依赖 | 7.97 MB，APP 内文件卡片直接可开 |

## 本轮新增经验
**「多角色一次生成」要挂基准图**：纯文生图合页在 4 个角色上无法稳定锁住画风与服装；把定稿层确定性拼成大画布再图生图，一致性由基准图承担。这也说明「画布大一点」不只是防裁切，还让每格角色有足够留白供后续 `contain` 与拖拽使用。

**边缘问题先量留白百分比，别急着修图**：4:5 稿像素没触边却看着要被切，因为左右只剩 2%。用「前景 bbox 四边距离 / 画布边长」量化，比只看 alpha 四边是否为 0 更能反映真实观感。
