## 你那句「贴图本来就是完整的，是载入时被裁了」是对的

v0.32 我误判成「源图自带直边」，去补了一圈不规则毛边，结果边缘发红发糊 —— **整批否决回退**。这版**一个像素不改图**：显示源回到 v0.31 的完整贴图（原始定稿 + 透明留白），零羽化、零毛边、零描边。

真正原因是**载入**：装角色的缩略图、资料库配图、全屏查看盒用了 `object-fit:cover`，竖版猫塞进横宽盒必然切头切脚。现在：

- 角色类容器统一 `contain`，只有场景板保留 `cover` 铺满
- 缩略图盒加高（82→96px / 54→64px），`contain` 后角色不再是窄窄一条
- 舞台角色四周留更宽安全边（80% 高 / top 3%），4 视口实测溢出 0px

**扩大载入范围，不动素材本身。**

## 借鉴成熟开源方案，落地两条工程约定

| 借鉴 | 落地 |
|---|---|
| Konva `fitContain()` / PixiJS Layout `objectFit` | 统一 `fitBox(cw,ch,iw,ih,mode)` 算等比居中矩形；`MutationObserver` 按「背景 cover / 立绘 contain」分层自动套用；小游戏玩家层 `drawImage` 也改用它，永不拉伸 |
| WebGAL `background/` 与 `figure/` 分层、Ren'Py `zorder`、interact.js `restrictRect` | `LAYOUT_RULES` 规则表：把散落的「出场景 34% / 进气泡 55% / 回弹 14 步×0.84 / 水平钳制」抽成声明式配置，判定函数只读规则 |
| W3C Pointer Events / Phaser 输入系统 | 小游戏鼠标 · 触屏 · 触控笔同一条事件流 + `setPointerCapture` |
| WCAG 2.5.7 | 拖动之外保留键盘与「💨 哈气」按钮单指针替代路径 |

详细对照见 `开源方案借鉴与落地_v0.33.md`。

## 小游戏：拖着猫走就能通关

原来只绑键盘，手机上没键盘就动不了。现在按住画布拖动，哈士喵**直接跟手**去吃书页，松手停下；键盘并存且不打架。触屏没有空格键，补了显眼的「💨 哈气」按钮，双击画布也能推开符文球。收集半径放宽 12px 适配手指精度。

实测：鼠标连续拖动 **5/5**、触屏 Pointer 拖动 **5/5**、键盘替代路径有效、碰撞或超时仍保留本关进度。
