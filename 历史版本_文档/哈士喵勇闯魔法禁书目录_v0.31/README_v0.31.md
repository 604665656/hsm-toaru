## 你猜对了：就是载入的宽高不够

连续三轮「茵蒂克丝、白井黑子、神裂有裁切」，前两轮都只在 **390×844** 小视口验收——那条媒体查询恰好把角色高度覆盖成 64%，所以本地一直「完整」，而你的手机 APP 预览是大视口，就一直被切。

真凶是一条半身模式 CSS：

```
.vn.frame-half .vn-char{ height:100%; top:8%; bottom:auto }
```

`top:8% + height:100%` → 角色底部永远落在**舞台高度的 108%**，而 `.vn` 是 `overflow:hidden`，于是脚掌、袍子下摆、刀尖被硬切掉约 8%。实测：

| 视口 | 舞台高 | 角色高 | 超出舞台 |
|---|---|---|---|
| 390×844 | 641 | 331 | 0（小屏规则碰巧救了） |
| 1024×768 | 542 | 538 | **41px** |
| 1170×2532 | 760 | 756 | **58px** |

**所有角色、所有宽视口都中招**，不是茵蒂克丝一个人的问题。

## 修复

- 统一改成 `top:2% + height:90%` → 底部 92%，任何视口都留 8% 安全边
- 追加 `max-height:92%` 通用兜底，副角色 `top:12% + height:44%`，全身模式 `height:76%`
- 所有立绘保持 `object-fit:contain`、脚贴底，不硬裁一寸
- 气泡默认透明度 `.30/.36 → .24/.29`（`--dlgA` 变量与设置滑块照常可调，有存档值则尊重存档），下半身进气泡也能透出来

**5 视口 × 3 关矩阵验收**：390×844 / 768×1024 / 820×1180 / 1024×768 / 1170×2532，最大溢出 **0px**，全部 `contain`，启动错误 0、破图 0。
