## 版本号规则

- 从 **v0.01** 开始，每次交付递增 `0.01`：v0.01 → v0.02 → v0.03 → v0.04 → v0.05 → v0.06 …
- 重大重制可跳位（如 v0.10）；同一轮只出一套文件，不覆盖旧版本目录。
- 版本号必须同时出现在：网页标题 / 顶部状态条 / 页脚、README 文件名、CHANGELOG 文件名、资料文档文件名、压缩包文件名。
- 每次交付固定包含：**游戏 HTML + Markdown 文档 + 压缩包**。

## v0.06 — 2026-11-07 · 换方案：两种像素 + 双 Core 猫身 + 21 只全是猫

### 用户要求

> 「有两个都不是猫，是人脸了，要重新生成，其他的也抠没了，换个方案，重新生成。」
> 并转述《纯色底实心角色层抠图方法》一页纸：
> 「抠图干净不是抠得厉害，是画的时候就只允许出现两种像素——一种是纯色背景，一种是完全实心的角色。」

### 问题定位（v0.05 → v0.06）

v0.05 的病根有两层，只调抠图阈值解决不了：

1. **身份漂移**：食蜂操祈、垣根帝督被生成端画成了人形少女／少年——圆滚滚猫头、尖猫耳、圆猫爪、蓬松卷尾全部消失，服装长在人身上。用户截图直接点出这两个。
2. **开口缝**：金发卷、帽檐、头巾、翼下、黑发下摆留了连通到画面边缘的幕色缝，floodFill 从四边扩散会顺着缝吃进角色内部 → 欧提努斯 23,050px、食蜂 20,584px、爱丽丝 18,946px 等大块「扣没了」。上一版「内部空隙补实」只覆盖**不与四边连通的封闭团**，挡不住开口缝。
3. 幕色不统一（01 号亮洋红 vs 其余暗紫红）且撞角色粉腮红／黑发暗部 → 边缘粉紫残留。

### 新增：双 Core 身份锚点（修人脸）

把「原作者眼镜猫三视图定稿」与「标准 Q 版猫身参考」（从 v0.05 本体层提取）合成一张 **双 Core 合页**，作为 10 次生成的唯一输入图。提示词把猫身写成最高优先级铁律：圆猫头占全身一半、尖猫耳粉内耳必须露在假发外、圆黑框眼镜、蓝色大圆眼、粉三角鼻、短圆猫爪（不是人手）、圆胖猫身、蓬松卷尾、额前白菱形毛纹；**严禁人类脸／人类五官比例／人类脖颈肩膀／人形身材／人手／人腿**，服装道具只是戴在猫身上的小配件。21 个角色**一张旧图没复用**，全部重画，没有一张人脸。

### 工程适配（不改方法口径）

- 源图是双人／三人合页：先整图键控 + 抹右下角水印 → 按角色像素列投影谷底分格 → **每格独立跑 `largest / fill_holes / despill / finish`**，否则最大连通域只会保住一个角色。
- 输出保持宽高比（480px 等比高度），不做方形 `resize`，避免 Q 版猫身被压扁。
- 两道收尾（对应踩坑第 4 条）：完全透明区 RGB 用 inpaint 填成邻近前景色，防止 LANCZOS 缩放把品红混进边缘；半透明边缘按 `C_fg=(C_obs−(1−a)·C_bg)/a` 反解幕色，换背景不串色。
- 曾试过「轮廓边缘带宽松判据 inpaint」清生成端淡粉描边，反而把不透明区品红残留从 40px 抬到 140px，**已回退**，不做过度修图。
